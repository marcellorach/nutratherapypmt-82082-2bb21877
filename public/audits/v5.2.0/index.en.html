1. Executive summary

The Senex AI platform (public brand; internal successor to VetGraphRAG/VetMedGraph, operated exclusively by PetMoreTime) is a veterinary clinical decision-support system focused on metabolic and degenerative conditions in canines, supported by a 5-layer causal Knowledge Graph (Compounds → Mechanisms → Pathways → Conditions → Outcomes), hybrid recommendation limited to 8 synergistic compounds per patient, a sigmoidal (Gompertz) Digital Twin per breed, and a HITL (Human-In-The-Loop) pipeline that prevents the integration of any triplet or population insight without curatorial approval.

Status as of 05/31/2026:

  • 18 consolidated strengths, highlighting a strict no-mock policy, PT/EN bilingualism with i18n versioning, RLS + has_role on all critical tables, gatekeeper curation now extended to population insights, standardized SNOMED-CT VetSCT + UMLS taxonomy, and mandatory quantitative evidence validation.
  • 9 gaps (down from 12 → 9 since v5.1.0): 3 mitigated during the period (partial formal PCCP, HITL population validation, quantitative evidence).
  • 4 risks (down from 5 → 4): LLM drift mitigated by server-side validation + provider fallback.

  • 67 Edge Functions deployed; 8 active prompts in ai_prompt_versions; 97 public tables; 6 users with roles; 668 pets (5 demo).
  • Knowledge Graph: 4,785 total triplets, 3,924 approved, 4,411 synchronized to Neo4j, 38,643 hierarchical_edges, 191 conditions, 81 breeds with Gompertz, 254 breed predispositions, 941 veterinary ontology nodes.

2. Glossary (13 key terms)

  • HITL — Human-In-The-Loop. A veterinary curator validates triplets and insights before promotion.
  • KG (Knowledge Graph) — 5-layer causal graph in Neo4j + Supabase relational mirror.
  • Triplet — (subject, predicate, object) extracted from a scientific study via LLM, with normalized strength and confidence.
  • Hierarchical Edge — A concrete edge in the graph derived from an approved triplet, with evidence_level and evidence_count.
  • L0–L4 — Ontology layers: Compounds (L0), Mechanisms (L1), Pathways (L2), Conditions (L3), Outcomes (L4).
  • RLS — PostgreSQL's Row Level Security; controls row-level access via has_role(auth.uid(), 'admin').
  • Digital Twin — Gompertz-based sigmoidal projection of canine longevity with years_gained per intervention.
  • Stack — Synergistic set of up to 8 compounds recommended for the patient.
  • Gap-fill pipeline — PubMed E-utilities search + Gemini structuring to fill in missing (compound × condition) pairs.
  • i18n_version — Cache-busting marker in src/i18n.ts; must be incremented with each bilingual change.
  • No-mock policy — All clinical data displayed comes from the real DB or an Edge Function; nothing is mocked.
  • Curation gatekeeper — Principle that isolates triplets/insights until manual approval.
  • SNOMED-CT VetSCT / UMLS — Canonical vocabularies for conditions and compounds.

5. Digestion Pipeline (7 Stages)

  1. Upload + dedup SHA-256 — blocks duplicate PDFs; Levenshtein on the title prevents re-uploads with slightly altered names.
  2. Chunking — semantic division for LLMs with a limited context window.
  3. Vectorization (text-embedding-004) — prerequisite for curation (the curator needs the "Source Snippet"). Centralized trigger at extract-study-entities via EdgeRuntime.waitUntil.
  4. Stage 1 — entity extraction (gemini-2.5-pro / gemini-3.1-pro-preview).
  5. Stage 2 — triplet extraction (high-quality models; adaptive chunking).
  6. Stage 3 — enrichment (intensity, dosage, species, evidence_level).
  7. HITL Curation — gatekeeper. Triplets with ≥50% confidence are auto-approved; <50% remain pending. Population insights (cohort_insights) have also undergone validation by a vet-curator since 05/27.

6. Vectorization and embeddings

  • Primary model: text-embedding-004 (768 dimensions via pgvector).
  • Legacy models in coexistence: 44 distinct versions registered in embedding_model_version (P1 gap: consolidated migration pending).
  • Current coverage: 13 studies processed with 1,342 distinct vectorized chunks.
  • RPC function: search_study_chunks(query_embedding, match_study_id, match_threshold=0.7, match_count=5).
  • Index: HNSW on study_embeddings.embedding.

9. Knowledge Graph (Neo4j + Supabase mirror)

  • Canonical IDs: always node.properties.id (Supabase UUID), never elementId (core memory).
  • Synchronization: approved triplets (curation_status='approved') sync to Neo4j; a trigger resets synced_to_neo4j upon demotion.
  • UI Rendering: react-force-graph-3d with WebGL to scale to 38k+ edges.
  • Live counts (05/31): 4,785 total triplets · 3,924 approved (82%) · 4,411 synced · 38,643 hierarchical_edges · 191 conditions · 941 vet_ontology_nodes.

10. Patient analysis — 6 stages

  1. Capture — structured form + AI extraction from exam PDFs (parse-pet-exam-pdf).
  2. Canonicalization — condition-name-localizer, lab-flag-canonicalizer, clinical-name-canonicalizer.
  3. Cross-reference — clinical-discovery-cross-reference-analysis correlates labs/meds/conditions/breed.
  4. Patient subgraph — useTreatablePathways trims the KG to relevant conditions/compounds.
  5. Stack therapy — hybrid recommendation limited to 8 synergistic compounds.
  6. Projection — Sigmoidal Digital Twin with years_gained adjusted by breed.

11. Hybrid recommendation (ch 8)

  • The condition-insights edge function consumes the pet's complete clinical context.
  • Product rule: maximum of 8 compounds per stack, deduplication by alphanumeric key.
  • Human-readable names (no nmn_v2_internal); KG fallback when data is missing.
  • Clinical transparency: any recommendation without raw KG data is flagged (in-memory principle).

12. Sigmoidal Digital Twin (Gompertz)

  • 81 breeds with individual curves.
  • evidence-based-projection-engine calculates baseline severity × sigmoidal outcome.
  • Gap P1: some breeds still lack a fine-tuned curve (generic default is applied).

25. Appendix A — Main SQL Schema

-- Roles
CREATE TYPE app_role AS ENUM ('admin','moderator','user');
CREATE TABLE user_roles (id uuid PK, user_id uuid → auth.users, role app_role);

-- Mirror KG
CREATE TABLE triplet_extractions (id uuid PK, study_id uuid, subject_name text,
  predicate text, object_name text, confidence numeric, evidence_level text,
  curation_status text DEFAULT 'pending', synced_to_neo4j bool DEFAULT false);
CREATE TABLE hierarchical_edges (id uuid PK, triplet_id uuid, source_type text,
  source_id uuid, target_type text, target_id uuid, relationship text,
  confidence numeric, evidence_count int, evidence_level text);

-- Embeddings
CREATE TABLE study_embeddings (id uuid PK, study_id uuid, chunk_index int,
  chunk_text text, embedding vector(768), chunk_metadata jsonb,
  embedding_model_version text);

-- Auditing
CREATE TABLE technical_audits (id text PK, version text, audit_date date,
  system_version text, system_changelog_date date, scope text, html_path text,
  pdf_path text, docx_path text, summary jsonb, superseded_by text);
CREATE TABLE audit_requests (id uuid PK, scope text, system_version text,
  system_date date, status text, fulfilled_audit_id text, requested_at date,
  auto_triggered bool DEFAULT false);
CREATE TABLE audit_settings (id bool PK CHECK(id=true), change_threshold int DEFAULT 6,
  watched_areas text[] DEFAULT ARRAY['curation','kg',...]);
